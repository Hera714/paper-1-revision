# 实现细节变更日志

> 用途：持续记录在不改变论文整体 pipeline 框架前提下进行的代码细节修复、原因、实验影响，以及论文需要同步修改的内容。
> 当前基准日期：2026-10-13。

## 1. 变更控制原则

### 1.1 默认保持不变的整体框架

以下内容视为论文方法的主体结构，默认不得自行改变：

1. 保留四条处理路线：`line0_pure_vlm`、`line1_base`、`line2_orientation`、`line3_bbox`。
2. 主实验使用仅基于问题文本的自动路由器；不得向路由器输入数据集类别、子类别、答案选项或图像。
3. 路由完成后，仍按照所选路线注入对应知识；知识注入阶段和总体方式保持不变。
4. 非直答路线维持“对象提取 → 深度/三维回投 → 场景图/符号关系 → 最终推理”的总体数据流。
5. `line0_pure_vlm` 保持为直接视觉语言推理路线。
6. 消融实验仍采用逐步移除模块的总体设计，除非后续另行讨论。

### 1.2 可直接进行并必须记录的细节修改

- 输出解析、JSON 读取和容错修复。
- 提示词的格式约束、歧义消除和证据使用说明。
- 中间结果、诊断字段、计时字段和可复现性信息的补充。
- 生成长度、thinking budget、随机种子和运行配置的合理调整。
- 对明显过强或互相矛盾的符号规则进行保守化处理。
- 不改变模块输入输出语义的对象命名、粒度和字段修复。
- 独立的新输出目录、重评分脚本和小规模验证配置。

### 1.3 必须先与作者讨论的大改动

- 新增、删除、合并或重新定义处理路线。
- 让自动路由器读取图像、答案选项、类别或子类别。
- 更换核心 VLM、深度模型、三维回投方法或知识来源。
- 改变知识注入阶段，或把知识直接用于路由决策。
- 改变非直答路线的主要阶段顺序或删除核心阶段。
- 新增需要训练的路由器、分类器或额外学习模块。
- 更换数据集划分、评价指标、答案标注或主要实验协议。
- 为个别测试样本加入硬编码关键词、答案或特例。
- 任何可能改变论文方法图、核心公式或主要创新点的架构调整。

### 1.4 操作约束

- 细节修改可以直接实施，但必须先小规模验证并记录。
- 大规模完整实验在启动前应单独确认运行时机和算力预算。
- 原始结果不得覆盖；每个版本使用独立输出目录。
- 论文表述在实验冻结后统一修改，但相关影响必须先记录在本日志。

## 6. 论文后续需要同步修改的内容

### 方法部分

- 主设置改为仅问题文本的 VLM controller。
- 明确路由器看不到类别、子类别、答案选项和图像。
- 说明路由后仍按所选路线注入知识。
- 明确二维坐标、深度、三维位置、bbox 尺寸和姿态证据的适用范围。
- 将预计算关系描述为辅助证据，并说明估计误差和不确定性。
- 输出解析属于工程实现细节，不包装成方法创新。

### 实验与局限性

- 固定并报告答案解析协议、生成长度和 thinking budget。
- 报告原始分数与解析修复后分数的差异。
- 新全量实验完成后再更新主表。
- 报告路线分布、解析失败率、Unknown 比例和分阶段延迟。
- 单目深度和 bbox 回投是近似尺度，遮挡时误差更大。
- 二维 profile 不能唯一确定三维朝向；底层 VLM 仍可能误判。
