# 第三关：现有几何证据的使用范围

日期：2026-10-15。目标是在不改动原 pipeline 架构、不增加新空间表征、不改知识库的前提下，检验某些问题是否被“离相机的深度/3D 坐标”误导。前一关的对象补提取在 46 道高风险候选上 `audit` 26/46、`repair` 23/46，故当前保持关闭；本关从原版 v4 缓存出发，不叠加补提取。

## 问题证据

原版最终阶段会向 `line1_base` 注入每个对象的图像点和 X/Y/Z 坐标，向 `line2_orientation`/`line3_bbox` 注入图像点、对象属性和预计算关系。现有提示已经提醒模型“画面上下左右优先看像素”“离某物体近不是离相机近”，但部分 thinking 仍用单点深度去判断参照物之间的最近关系、画面位置或“之间”。例如 ID 404 在补入花后按花与吊灯的相机深度差误选吊灯；ID 1455 只补到一栋建筑后，又用深度误选树。另一类错误是把底部对齐用于顶部对齐（ID 854）或把图像角点改为相机远近；这些需要先证明筛选已有证据确有收益，再考虑主代码改动。

本轮仅验证**最终阶段的证据呈现**，不重新运行路由、对象提取、深度模型或关系生成。

## 唯一实验因素

新脚本：`3dkar-repro-v2/scripts/replay_geometry_evidence.py`。服务器路径：`/root/autodl-tmp/paper-1-revision/scripts/replay_geometry_evidence.py`。

每题两组使用同一原图、原问题与选项、原选路、原场景图缓存、原关系缓存、原知识文本、模型、seed 和答案解析方式：

- `full`：按原版 v4 的方式把完整场景图和预计算关系交给最终推理。
- `scoped`：把该题的数值相机深度、全局 3D 坐标及依赖它们的预计算关系从最终阶段输入中省去；保留原图，以及缓存对象的像素点、可用 bbox 和可见朝向/轮廓。仍按原路线注入原知识文本。

为了让模型知道缺少 3D 坐标是有意的，`scoped` 附一条简短说明：相机深度/3D 坐标在本题被省去，像素点只是锚点而非物体边界。这意味着本次测试的是**证据范围与其呈现方式的组合**，不能把将来的任何准确率变化只归因于“删除 Z 数值”。若测试通过，正式 pipeline 应再以可选开关重做单因素验证。

触发仅由推理时可见的**问题文字**决定，且比较保守：

1. 明确问图像/照片/画面中的顶部、底部、中心、角落、左右或中间；
2. 问“离某个具名参照物最近/更近/最远”，排除相机、观察者等相机中心参照；
3. 明确问“什么/哪个物体在……之间”，排除“……之间的关系/距离/差异/角度”等一般性问法；
4. 若题目显式询问深度、前景/背景、遮挡或前后关系，则不触发本次筛选。

不读取 `Category`、`Sub_Category`、GT 或旧预测来决定单题使用哪种证据。旧预测正确性仅用于固定实验样本的错/对平衡。

## 固定样本与文件

在 1400 条旧结果中，78 题满足上述保守触发且走场景图路线。已用 seed `20261015` 从其中固定抽取 **48 题**：原版答对 24、答错 24；再加入 **11 题机制案例**，与抽样题重叠 7 题，合计 **52 个唯一 ID、104 次最终推理**。抽样的路线分布为 line1 40、line2 5、line3 3；触发类型为“之间”21、画面位置10、具名参照最近17。故这个小测主要反映 line1 风险，line2/line3 样本不足以作路线级结论。

正式 manifest：

```text
/root/autodl-tmp/paper-1-revision/outputs/geometry_evidence_pilot_v2/manifest.json
```

manifest 已记录原预测和数据集的 SHA256，并在运行时核对；结果将写入同目录的 `predictions.jsonl`、`summary.json`、`replay_meta.json`。较早准备的 `geometry_evidence_pilot/manifest.json` 是未运行的初稿，触发条件过宽；**本轮只使用 `_v2` 路径**。

## 验证与运行边界

CPU 已完成脚本语法检查和触发规则、几何字段省略的边界检查；模型文件存在，正式 manifest 已生成。未启动 GPU 推理。按上一轮知识重放的相同最终阶段计时推算，104 次推理约 20 分钟，加模型加载和机器波动后应多预留时间。

由用户在服务器运行：

```bash
conda activate ovis
cd /root/autodl-tmp/paper-1-revision
export OMP_NUM_THREADS=8
python scripts/replay_geometry_evidence.py run \
  --manifest outputs/geometry_evidence_pilot_v2/manifest.json \
  --config configs/auto_revision_v4.yaml \
  --output-dir outputs/geometry_evidence_pilot_v2
```

脚本记录每题两组的输入缓存指纹、知识指纹、显示证据指纹、thinking、答案和耗时；中断后可用同一命令续跑。结束时应有 104 条 `ok`，样本 48/48 成对、机制题 11/11 成对。两个集合有 7 题重叠，不可相加为独立题目。

## 判定标准与下一步

先核对两组缓存/知识/seed 完全配对，再比较错→对、对→错、`Unknown` 和耗时，重点查看图像位置、具名参照最近和“之间”三种触发各自的变化。出现净收益也只说明这批已接触的开发题有改善；不能直接据此宣称全量提高。若出现明显退化或 `Unknown` 增加，应停止该策略并复核误伤；若收益稳定且没有集中退化，再考虑以默认关闭的开关接入原 pipeline，在另一批固定题上复验，之后才讨论完整 1400 题。
